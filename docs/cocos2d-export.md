Cocos2d Export (`.lkot` / `.lkob` / `AnimNameDef_*.h`)
======================================================

This document is the schema reference for the **runtime export** that
`SpriteState::exportSprite()` produces (see `src/spritestate.cpp`).
Whereas `.lvks` (see `lvks-format.md`) is the **authoring** format used
by the editor for save/load, the Cocos2d export is the bundle the
*game* loads: a binary blob of frame pixmaps, a text manifest, and a C
header of animation-name macros.

The export pipeline is the default behavior of
`exportSprite(filename, outputDir, postpScript)`; JSON-atlas output
(`.png` + `.json`) is documented in [`json-export.md`](json-export.md)
and is selected with `ExportFormat::Json`.

## File set

For input `filename = "<dir>/<base>.lvks"` and `outputDir = <out>`,
`exportSprite()` writes three files:

| Path                                       | Format            | Description                                  |
| ------------------------------------------ | ----------------- | -------------------------------------------- |
| `<out>/<base>.lkob`                        | binary blob       | Concatenated PNG-encoded frame pixmaps.      |
| `<out>/<base>.lkot`                        | text manifest     | Frame index + animation/aframe records.      |
| `<out>/AnimNameDef_<base>.h`               | C header          | `#define ANIM_<name>` macros for animations. |

`<base>` is `QFileInfo(filename).baseName()` -- the input filename
stripped of its directory and the first dot-extension. The naming
convention is fixed; there is no override.

Path safety: `<base>` is run through `isSafeExportPath()` before any
file is opened, so a hostile `<base>` containing path separators or
"`..`" is rejected with `ErrUnsafeOutputPath`.

## `.lkob` -- binary frame blob

Pure concatenation of PNG byte streams. There is no header, no length
prefix, and no delimiter between records. Frames are emitted **in
ascending `frameId` order**, and only frames that are referenced by at
least one animation (`SpriteState::isFrameUnused(frame.id) == false`).

Each frame's bytes are produced by `writeImageWithPostprocessing()`:
the frame's pixmap is rendered to a temporary PNG (compression level
9), optionally piped through a user-supplied `postprocessing-script`
(which receives the input PNG path as `argv[1]` and writes its output
to the path passed as `argv[2]`), then the result is read back and
appended verbatim to the `.lkob` file.

The companion `.lkot` text manifest provides the offset/length index
into this blob; without `.lkot`, the `.lkob` blob is opaque.

## `.lkot` -- text manifest

Text, line-oriented, one record per line. The layout is:

```
### Exported LvkSprite ################################
Exported LvkSprite version 0.4

# Frame Pixmaps
# format: frameId,offset(bytes),length(bytes)
fpixmaps(
    <frame-id>,<offset>,<length>
    ...
)

# Animations
# format: animationId,name,flags
# Animation frames
# format: aframeId,frameId,delay,ox,oy,sticky
animations(
    <animationId>,<name>,<flags>
    aframes(
        <aframeId>,<frameId>,<delay>,<ox>,<oy>,<sticky>
        ...
    )
    ...
)

### End Exported LvkSprite ############################
```

Notes:

- The version header is always `Exported LvkSprite version 0.4`
  (`HEADER_VER_04`), independent of the input `.lvks` version. The
  exported aframe rows are always 6-field (`sticky` is emitted), so v0.4
  is the only honest header.
- `fpixmaps` rows give the byte offset and byte length of each frame
  inside the sibling `.lkob`. Slicing `.lkob[offset, offset+length]`
  yields one PNG.
- Frames present in `_frames` but unused by any animation are
  **omitted** from both `.lkob` and the `fpixmaps` index.
- Aframes inside each animation are sorted by `aframeId` ascending at
  export time -- the same canonicalisation `SpriteState::save()` applies
  to `.lvks` (see "Canonical form" in `lvks-format.md`).
- `animations()` rows are 3 columns: `id,name,flags` (matching the
  v0.3+ schema; `.lkot` is always written as the latest version
  regardless of source file). The same `flags` value is also surfaced
  via `#define ANIM_<name>_FLAGS` in the macro file (below).

## `AnimNameDef_<base>.h` -- C header

C preprocessor header with one `#define` per animation, for the game's
animation lookup code. The layout is:

```c
// File autogenerated by LvkSprite version 0.4
// -- DO NOT EDIT OR MODIFY THIS FILE --

#ifndef __<sanitised_header_path>__
#define __<sanitised_header_path>__

#define ANIM_<name>            "<name>"
#define ANIM_<name>_FLAGS       0x<flags-hex>
...

[optional custom_header content]

#endif //__<sanitised_header_path>__
```

Note the include guard is derived from the **full output path** of the
header (`getMacroName(outputDir + "/AnimNameDef_<base>.h")`), not just
the basename -- e.g. exporting into `/tmp/out` produces a guard like
`___TMP_OUT_ANIMNAMEDEF_MARIO_H__`. Two exports of the same sprite into
different directories therefore get different guards.

Macro-name rules (see `getMacroName()` in `src/spritestate.cpp`):

- Each animation `name` is converted to a valid C identifier by
  walking Unicode codepoints and collapsing every non-`isLetterOrNumber`
  character to `_`. Adjacent underscores are coalesced.
- An empty result (e.g. an all-punctuation or all-CJK name that
  sanitises to nothing) becomes `UNNAMED`.
- Duplicate macro names get a `_2`, `_3`, ... suffix (handled in
  `exportSprite()` after sanitisation) so two distinct animations
  whose names collide on sanitisation still produce distinct
  `#define`s.
- The macro value is the **original** `name` string (so the runtime API
  still resolves correctly when the macro is used as a lookup key).

If the source `SpriteState` has a non-empty `customHeader`, its
content is inserted between the `#define ANIM_...` block and the
`#endif`, fenced by `// starting custom header data` /
`// end custom header data` markers. See `lvks-format.md` for the
verbatim/whitespace caveat on `customHeader` round-tripping through
`.lvks`.
